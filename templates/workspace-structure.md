# Структура навчальної теки

Скіли Tyama пишуть файли за домовленими шляхами. Теки створюються **на ходу** — заздалегідь
нічого робити не треба. Цей документ пояснює, що звідки береться, щоб потім не дивуватись.

Усі шляхи — **відносні від кореня твоєї навчальної теки**. Де вона лежить, скіли не знають
і знати не мають.

---

## Що куди пишеться

```
<твоя навчальна тека>/
├── .claude/
│   └── learner-profile.md        # необов'язково: профіль лише для цього проєкту
│
├── <категорія>/<тема>/           # напр. bd/sql/, docker/volumes/
│   ├── <тема>_plan.md            # teach-concept, режим A: карта теми
│   ├── <тема>_learn.md           # teach-concept, режим A: повний матеріал
│   ├── <тема>.html               # необов'язково: візуальна версія
│   ├── quiz_log.md               # recall-quiz
│   ├── feynman_log.md            # feynman-drill
│   ├── build_log.md              # build-project-drill
│   ├── audit_log.md              # course-audit
│   ├── errors/                   # error-decoder, якщо просив зберегти
│   └── anki/                     # anki-cards: 3 файли колоди
│
├── interview/<стек>/             # банк питань + mock_log.md (interview-mock)
├── system-design/                # задачі + drill_log.md (system-design-drill)
├── algoritm/                     # задачі, stats.md (leetcode-coach)
├── common-mistakes/              # типові помилки: джерело trap-питань
├── life-skills/                  # побутові навички: electrics/ та твої власні коучі
└── retro/                        # learning-retro: HTML + PDF звіти, retro_log.md
```

Категорії ти вигадуєш сам. `teach-concept` подивиться, що вже є, і створить нову теку
за тією ж логікою — або спитає, якщо не зрозуміло.

---

## Той самий набір у Google Drive

Якщо в профілі стоїть `сховище: drive`, структура **не змінюється** — міняється лише корінь.
Замість твоєї теки на диску всі ті самі шляхи живуть усередині теки `Tyama/` у Drive:

```
Tyama/
├── learner-profile.md
├── bd/sql/
│   ├── sql_plan.md
│   ├── sql_learn.md
│   └── quiz_log.md
├── interview/python/
└── retro/
```

Нащо це: Drive читається і пишеться **і з Claude Code, і з застосунку на телефоні**.
Один набір даних на всі середовища, без синхронізації руками.

Що варто знати:

- Теку `Tyama/` асистент створює сам при першому записі. Є — не перестворює
- Логи **дописуються**, а не перезаписуються. Затертий `quiz_log.md` — це втрачена історія
  твоїх слабких місць
- Конектор відмовив — асистент **скаже про це**, а не промовчить, і віддасть текст блоком
- Якщо теку розшарено — твої логи бачать усі, хто має посилання. Там записано, де в тебе
  провали. Не шар без потреби

## Якщо теки немає

Це **не помилка**. Скіли працюють без будь-якого з цих файлів:

| Ситуація | Поведінка |
|---|---|
| Немає `interview/<стек>/` | `interview-mock` скаже, що банку питань немає, і не вигадає питань |
| Немає `_learn.md` | `anki-cards` запропонує спершу створити матеріал |
| Немає `common-mistakes/` | trap-питання просто не буде, решта працює |
| Немає `MEMORY.md` | працює без нього, профіль бере з `learner-profile.md` |

## Якщо тека під git

Навчальні матеріали — **особисті нотатки, не код**. Плани, логи й ретро в репозиторії
нікому не потрібні, а логи ще й містять твої слабкі місця.

Додай у `.gitignore`:

```gitignore
# навчальні матеріали — особисті
*_plan.md
*_learn.md
*_log.md
retro/
**/anki/

# профіль — тим паче
.claude/learner-profile.md
```

Скіли нагадають про це один раз і **не редагуватимуть твій `.gitignore` самі**.

## Профіль: глобальний чи проєктний

| Файл | Коли потрібен |
|---|---|
| `~/.claude/learner-profile.md` | майже завжди — один профіль на всі теки |
| `./.claude/learner-profile.md` | тільки якщо в цьому проєкті потрібне інше: інша мова, інший рівень, інший контекст |

Проєктний перекриває глобальний. Обидва — поза плагіном, тому оновлення плагіна їх не чіпає.
