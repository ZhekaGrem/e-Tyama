# Середовище Tyama: профіль, ресурси та інструменти

Цей протокол однаковий для всіх агентів. `~` — домашня тека користувача,
`./` — корінь навчального простору, а не тека встановленого скіла.
Використовуй лише доступні інструменти та дозволені користувачем шляхи.

## Вибір профілю

1. Якщо користувач явно вказав файл профілю, використай його. Для вже обраного
   Drive-сховища профіль — `Tyama/learner-profile.md`; для чату — переданий текст профілю.
2. Інакше перевір локальні кандидати в такому порядку:
   - `./.tyama/learner-profile.md`;
   - `./learner-profile.md`;
   - `./.agents/learner-profile.md`, `./.codex/learner-profile.md`, `./.claude/learner-profile.md`;
   - `~/.tyama/learner-profile.md`;
   - `~/.agents/learner-profile.md`, `~/.codex/learner-profile.md`, `~/.claude/learner-profile.md`.
3. Перший наявний профіль стає активним; проєктний завжди перекриває глобальний.
   Якщо на одному рядку списку є кілька різних профілів агентів, попроси обрати один.
   Однакові копії — бери першу. Не зливай профілі й не перенось їх автоматично.
4. На початку сесії коротко назви активний шлях. Читай і оновлюй саме цей файл.
   Порожній профіль доповнює `setup-profile`; не підміняй його глобальним.
   Наявний або явно заданий файл недоступний — повідом про це; не оголошуй його відсутнім
   і не створюй заміну. Можна продовжити з профілем, який користувач передасть текстом.

Новий профіль: `~/.tyama/learner-profile.md`, а для явно обраного окремого
проєктного профілю — `./.tyama/learner-profile.md`. Наявний старий профіль
оновлюється на місці, зокрема в `.claude`. Створення й зміни — за `setup-profile`.
Якщо запис недоступний, віддай вміст для копіювання і скажи, що його не збережено.
Не змінюй вибране сховище курсів через відсутність інструментів у поточному чаті.

## Ресурси та виклик скілів

- Цей файл лежить у `skills/_shared/`. Посилання `skills/_shared/...` у скілах
  означають сусідню теку `../_shared/` від теки поточного `SKILL.md`, незалежно від cwd.
- `references/...` відлічуються від теки поточного скіла. Сусідній скіл —
  `../<назва>/SKILL.md`. При встановленні зберігай усю теку `skills/`, включно з `_shared`.
- «Запусти скіл» означає використати доступний механізм середовища або прочитати його
  `SKILL.md` і виконати інструкції в поточній розмові. Окремий агент не потрібен.
  Немає файлу чи інструмента — назви відсутню можливість, не вигадуй результат виконання.
- `Read`, `Write`, `Edit`, `Bash`, `WebSearch`, `WebFetch` — назви можливостей:
  використовуй відповідні інструменти свого середовища. Команди адаптуй до ОС та shell.
  Без вебдоступу не стверджуй, що перевірив актуальність джерел.
- Drive потребує фактичних можливостей читання і запису конектора. Конкретні назви
  інструментів і підтримувані формати перевіряй у його описі. Без запису — блок для копіювання.
- У чаті без файлів користувач передає скіл, цей протокол, експертні стандарти,
  потрібні залежності та останню пам'ять текстом або вкладеннями. Профіль і пам'ять
  діють у поточному контексті; між чатами їх треба передати знову.
