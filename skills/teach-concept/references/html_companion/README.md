# HTML-супутник для курсів

Генератор вітрин за правилом C канону: `.md` — джерело, HTML — вітрина того самого змісту.
Правиш курс — перегенеровуєш сторінки. HTML руками не правиш.

## Що робить

Бере теку треку (наприклад `F:\Lessons\ai-teacher\ai-engineer`) і будує:

| Джерело | Сторінка |
|---|---|
| `<тема>/<prefix>_learn.md` | `<тема>/<prefix>_learn.html` |
| `roadmap.md` | `roadmap.html` |
| `README.md` | `index.html` — карта треку, плюс блок тем, яких README ще не згадує |

На кожній сторінці є:
- зміст із фільтром;
- Mermaid-діаграми;
- бейджі `[Співбесіда]` / `[Базовий]`;
- світла й темна тема;
- мобільне меню;
- навігація «усі теми» та «попередня / наступна» у порядку таблиці README.

Посилання між курсами (`../agents/agents_learn.md`, `../tool_calling/`) переписуються на сторінки, якщо ті існують.

Mermaid лежить один раз у `<трек>/_assets/mermaid.min.js`, тож сторінки легкі й працюють офлайн.
Якщо файлу немає, генератор один раз завантажує версію 11.15.0 з cdnjs.

## Як запустити

```bash
cd skills/teach-concept/references/html_companion
npm install
node build.mjs "F:/Lessons/ai-teacher/ai-engineer"
```

Наприкінці генератор друкує таблицю: сторінка, розмір, кількість діаграм, пунктів змісту й переписаних посилань.

## Перевірка після збірки

Генератор не знає, чи відрендерилась кожна діаграма. Перевір окремо в headless Chrome:

```bash
chrome --headless=new --virtual-time-budget=15000 --dump-dom "file:///<шлях>/<page>.html"
```

У кожному `<pre class="mermaid">` має бути `<svg`, без `Syntax error`.

## Чого не чіпає

- Самі `.md`. Генератор їх лише читає.
- Файли, що не є `_learn.md`, `roadmap.md` чи `README.md`: `_plan.md`, `_practice.md`, канваси. Посилання на них лишаються на `.md`.

## Git

Згенеровані курси — особисті матеріали учня, а не код. У `.gitignore` репозиторію є
`*_learn.html` і `mermaid.min.js`. Якщо тека курсів під git, додай ці рядки і туди.
