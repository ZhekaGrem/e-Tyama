Призначення: **самодостатній матеріал**. Учень може вчитись з одного файлу. Всі терміни пояснені при першій згадці, є приклади коду, є візуалізація, є секція співбесіди, є reflection diary.

## Формат терміна — КРИТИЧНО

Учень слабкий на термінологію і пам'ять. Цей формат не можна скорочувати.

**Для звичайного терміна:**
```markdown
**Index** (Індекс) — Покажчик / Індекс
Додаткова структура яка ПРИСКОРЮЄ пошук. Без індексу — Full Table Scan. 
Ціна: SELECT швидший, INSERT/UPDATE повільніші + місце на диску.
*Аналогія:* Зміст книги. Без нього гортаєш все, з ним — одразу потрібна сторінка.
```

**Для скорочення:**
```markdown
**SQL** — **S**tructured **Q**uery **L**anguage (Ескюел)
Переклад: Структурована Мова Запитів.
Мова якою ти "розмовляєш" з базою. <контекст, історія, стандарт>.
*Аналогія:* ...
```

**Для терміна з синонімами:**
```markdown
**Row** (Роу) — Рядок. Синоніми: **Record** (Рекорд — Запис), **Tuple** (Тапл — Кортеж)
<пояснення>
*Аналогія:* ...
```

**Для абревіатури (ACID, CRUD, REST) — завжди таблицею:**
```markdown
**ACID** — чотири гарантії надійності транзакцій:

| Літера | Повна назва | Вимова | Переклад | Суть | Аналогія |
|--------|------------|--------|----------|------|----------|
| **A** | **A**tomicity | Атомісіті | Атомарність | Або все, або нічого | ... |
```

## Принципи заповнення

1. **Словник (ЧАСТИНА 0) завжди перший.** Учень звертається до нього коли не пам'ятає термін.
2. **Кожен англ. термін — при першій згадці повний формат.** Далі можна без розшифровки.
3. **Мінімум 3-5 схем** у файлі. Для: зв'язків між сутностями, процесів, станів, архітектури. Формат — Mermaid або списки/таблиці за середовищем читання (`visual_patterns.md`). **Не дублюй одну схему двома форматами.**
4. **Код — з коментарями українською.** Коментар пояснює **чому**, не **що**.
5. **Кожен блок закінчується практичним.** "Що питають на співбесіді" або "типові помилки" або "як перевірити".
6. **Порівняння — таблицями, для КОЖНОЇ рекомендації.** Будь-яка порада («використовуй X», «вчи Y першим») має альтернативу і критерій: «X, бо ‹критерій›; якщо ‹умова› — тоді Y». Для 2+ варіантів (LEFT vs RIGHT JOIN, REST vs GraphQL) — таблиця: критерій / варіант 1 / варіант 2 / коли використовувати. Безальтернативні поради заборонені (лінза 2 канону).
7. **Reflection diary в кінці обов'язково.** Секція з шаблоном для заповнення після кожної сесії.

## Розмір

- Мала тема: 500-1500 рядків
- Середня тема: 1500-3000 рядків
- Велика тема (SQL, React, Kubernetes): 3000-8000 рядків

Якщо виходить понад 8000 — файл стає непрактичним. Розбивай на підтеми.
