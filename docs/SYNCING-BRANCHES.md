# Дві гілки, дві мови — і чому merge тут не працює

`main` — англійська, дефолтна. `ua` — українська.

Це **не** звичайні feature-гілки. Вони ніколи не зіллються назад, і це нормально.
Документ пояснює, як із цим жити, щоб через три місяці одна з мов не стала мертвою.

---

## Чому не merge

Гілки в git призначені **сходитись**. Переклад не сходиться ніколи: після перекладу
різні **всі** рядки скіла. `git merge main` у гілку `ua` дасть конфлікт у кожному
файлі, і розв'язати його можна лише вручну переписавши все заново.

Тому: **мовні файли між гілками не мержаться. Ніколи.**

---

## Що мержиться, а що ні

Перший коміт репозиторію був **мовно-нейтральним** навмисно — саме щоб не-мовні файли
мали спільного предка і залишались злитними.

| Файл | Мержиться? |
|---|---|
| `LICENSE` | так |
| `.gitignore` | так |
| `.claude-plugin/plugin.json` | так |
| `.claude-plugin/marketplace.json` | так |
| `skills/**/SKILL.md` | **ні** — переносити переказом |
| `skills/**/references/*.md` | **ні** |
| `templates/*.md` | **ні** |
| `README.md` | **ні** |
| `docs/*.md` | **ні** |

Для не-мовних файлів звичайний merge працює:

```bash
git checkout ua
git merge main -- .claude-plugin .gitignore LICENSE
```

---

## Як переносити зміну скіла

Припустимо, ти правиш `electrics-coach` на `ua`.

1. **Зроби зміну на одній гілці, доведи до кінця.** Не редагуй обидві паралельно.
2. **Занотуй, що саме змінилось** — не diff, а сенс: «додав таблицю струмів для 5 мм
   електрода», «прибрав пораду без альтернативи».
3. **Перейди на другу гілку і внеси ту саму зміну переказом.** Не копіюй diff — переклади
   думку. Технічні числа й назви переносяться як є.
4. **Звір структуру, не текст:** ті самі секції, той самий порядок, ті самі заголовки.
   Якщо на `ua` з'явилась секція «Формат підсумку сесії» — на `main` має бути
   «Session summary format» у тому ж місці.

```bash
git checkout ua      # правиш тут
# ... зміни, коміт ...

git checkout main    # переносиш сюди переказом, не мержем
# ... ті самі зміни англійською, коміт ...
```

## Як не дати гілкам розійтись

**Правило одного заходу.** Не залишай зміну на одній гілці «на потім». Перенеси в той
самий день, поки пам'ятаєш сенс правки. Борг у два тижні перетворюється на «простіше
перекласти файл заново».

**Перевірка структурного паритету** — те, що можна автоматизувати. Кількість секцій
і заголовків має збігатися:

```bash
git show ua:skills/electrics-coach/SKILL.md   | grep -c '^#'
git show main:skills/electrics-coach/SKILL.md | grep -c '^#'
```

Числа різні — гілки розійшлись структурно, а не лише мовою. Це і є сигнал.

**Файли теж мають збігатися:**

```bash
diff <(git ls-tree -r --name-only ua) <(git ls-tree -r --name-only main)
```

Порожній вивід — набір файлів однаковий. Різниця означає, що десь скіл додали лише
в одну мову.

---

## Якщо одна гілка все-таки відстала надовго

Не намагайся наздогнати diff-ами — це найдовший шлях. Візьми **актуальну** версію файлу
з провідної гілки і переклади її цілком заново. Швидше і чистіше, ніж збирати
пів року правок по одній.
